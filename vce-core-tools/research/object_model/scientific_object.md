# Scientific Object

## Purpose

A Scientific Object is the primary unit of epistemic evolution within the VCE Research Program.

It is not a document, file or representation.

A Scientific Object is a persistent epistemic entity whose identity, type, state, relationships, evidence, history and representations can be reconstructed across time.

Documents are representations of Scientific Objects.

---

# Formal Structure

A Scientific Object is represented as:

SO = (ID, Type, State, Metadata, Relationships, History, Representations)

---

# Universal Components

## ID

Persistent identifier.

The ID never changes.

---

## Type

Defines what kind of epistemic entity the object is.

Type is immutable.

Examples:

- Observation
- Research Question
- Experiment
- Evidence Card
- Architectural Decision

---

## State

Defines the current epistemic standing of the object.

State evolves through governed transitions.

Examples:

- Candidate
- Active
- Supported
- Accepted
- Revised
- Deprecated
- Historical

---

## Metadata

Descriptive information about the object.

---

## Relationships

Links to other Scientific Objects.

Examples:

- supports
- contradicts
- derives_from
- revises
- depends_on

---

## History

Record of state transitions, revisions and decisions affecting the object.

---

## Representations

Concrete formats through which the object is expressed.

Examples:

- Markdown
- YAML
- JSON
- PDF
- Knowledge Graph Node
- API Resource

Representations may change.

The Scientific Object persists.

---

# Architectural Role

Scientific Objects are governed by the Corpus.

Scientific Objects are indexed by the Registry.

Scientific Objects are transformed by the Laboratory.

Scientific Objects may be generated by Scientific Instruments.

Scientific Objects may be supported by verifiable execution from the Runtime.

---

# Governing Principle

Representations are replaceable.

Scientific Objects are persistent.

---

# Adoption Rule

The Scientific Object abstraction shall not automatically replace the current Registry implementation.

The abstraction must first demonstrate utility through use in new artifacts.

Only after sustained operational value is observed may the architecture migrate toward an object-oriented Registry.
