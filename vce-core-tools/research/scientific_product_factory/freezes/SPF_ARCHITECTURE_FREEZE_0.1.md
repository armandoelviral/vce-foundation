# Scientific Product Factory Architecture Freeze

Artifact ID: SPF-FREEZE-0.1

Version: 0.1

Status: Active Baseline Candidate

Classification: Architecture / Freeze

Owner: Scientific Product Factory

---

# Purpose

Establish the first reconstructible architecture baseline for the Scientific Product Factory before implementation of SP001.

This Freeze does not declare the architecture complete.

It defines the architecture that shall be implemented, tested and challenged through operational evidence.

---

- Institutional Capability Lifecycle

- Platform Services
- Service Taxonomy
- Canonical Event Contracts
- Aggregate Contracts
- Capability Dependency Graph

---

# Stable Decisions

## Core Independence

The Core remains domain-independent.

Vertical Packs may depend upon the Core.

The Core shall not depend upon any Vertical Pack.

---

## Human Authority

Artificial Intelligence analyzes, simulates and recommends.

Human expertise contributes judgment and organizational intent.

Governance determines permanence.

---

## Evidence Priority

Operational evidence has priority over architectural assumptions.

Implementation evidence may invalidate or revise this Freeze.

---

## Capability Orientation

The primary long-term outcome of a Scientific Product is Institutional Capability Growth.

Automation remains a mechanism rather than the objective.

---

## Event-Driven Collaboration

Bounded Contexts collaborate through governed, immutable and versioned events.

Deployment topology remains undecided.

---

## Knowledge Promotion

Expert decisions and successful outcomes do not automatically become policy or capability.

Promotion requires evidence accumulation and governance review.

---

# Candidate Decisions Under Validation

The following elements remain candidates and shall not be treated as permanent architecture:

- Organizational Case as Aggregate Root
- Capability Operating System
- Dedicated Capability Registry
- Dual Graph Architecture
- Expertise Event Sourcing
- Institutional Capability Layer as a sixth VCE layer
- Scientific Product Factory evolution toward Institutional Capability Factory

---

# Implementation Target

The first implementation target is:

SP001 — Retail Reference Implementation

SP001 shall validate:

- Core and Vertical separation
- event contracts
- bounded context boundaries
- capability lifecycle
- human expertise capture
- operational evidence capture
- governance workflows
- institutional memory
- capability promotion

---

# Evidence Requirements

Implementation shall produce evidence regarding:

- boundary violations;
- unnecessary services;
- missing responsibilities;
- event contract instability;
- aggregate consistency;
- workflow complexity;
- governance friction;
- expert adoption;
- capability growth;
- operational cost.

---

# Change Rule

Any modification to this baseline shall require:

1. implementation evidence;
2. explicit impact analysis;
3. architecture review;
4. versioned Freeze replacement.

No architectural change shall remain implicit.

---

# Exit Criteria

Architecture Freeze 0.1 may be superseded when:

- the SP001 skeleton is executable;
- at least one end-to-end workflow is implemented;
- event contracts are exercised;
- architectural candidates receive evidence;
- implementation findings are recorded;
- Architecture Freeze 0.2 is issued.

---

# Baseline Outcome

SPF Architecture Freeze 0.1 marks the transition from architecture discovery to implementation-driven validation.

From this point forward, software execution becomes the primary source of architectural evidence.
