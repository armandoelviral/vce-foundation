# HAS Runtime Specification Style Guide

Version

1.0

Status

Draft

---

Every executable specification section shall
follow the same structure.

1. Purpose

Describe why the concept exists.

2. Domain Definition

Define the concept independently from any
implementation.

3. Runtime Semantics

Describe the observable behavior expected
from the Runtime.

4. Constraints

List everything that is explicitly forbidden.

5. Guaranteed Properties

Describe the properties that every
implementation must preserve.

6. Verification

Reference the executable tests that validate
the specification.

No additional sections should be introduced
without explicit architectural justification.

---

All executable specifications shall conform
to the Runtime Specification Grammar.
